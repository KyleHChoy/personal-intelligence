# @intelligence/personal-models

The model port of Personal Intelligence, to two vendors: OpenRouter and Anthropic's Messages API. Against OpenRouter it is the shared `ModelClient`, one system and one user message and never tools, to `openrouter.ai`, with the same provider fields (`data_collection: "deny"`, `require_parameters: true`) on every request and no `temperature`. Against Anthropic it is the same extraction port and the reasoner's turn (`createAnthropicExtractClient`, `createAnthropicTurnModel`, below), to `api.anthropic.com`. `withBudget` refuses a call before it is sent once a run's or a day's spend, with what the calls in flight have reserved, or the run's number of calls, has reached its bound.

Two models appear here by role. Code and docs call them by two names: Jev, the rung 1 screening model, and Luna, the rung 2 extraction model class. The screening model, the decide model at rung 1, is the one id in `DECIDE_MODELS`, on OpenRouter's Decisions surface: it answers each fixed question with a probability. The extraction model reads an item and writes its claims; which one is the deployment's configuration (`PI_EXTRACT_MODEL`), not this package's.

An error the vendor answered with a status is a `ModelClientError` (`refused` or `unavailable`) that also carries `status`, a fixed code such as `http_404`, and nothing of the body. `complete` checks a request with the shared `checkCompletion` against the caller's registry, refuses tools and messages whatever the prompt allows, sends one request with `redirect: "error"` and a 60 second deadline, retries a transport failure, a 408, a 429 or a 5xx at most three times in all, and reads the answer in this order: no answer is `unavailable`; a tool call, a cut-off answer and a filtered answer are `ModelOutputRejected`; anything else goes to the shared `validateOutput`. `onUsage` is awaited once for every answer, before its verdict is acted on, with the cost in micro-dollars and the configured model id. Every answer is checked again by the shared `completeWithReplay` when the caller goes through it.

- **May import:** `@intelligence/contracts`, and nothing else in this repository, so an agent loop may import it.
- **Runs with:** no credentials of its own. It is handed the OpenRouter key, a `fetch` and a clock. Nothing under `src/` reads the environment, a file or the console.
- **Must never:** reach a database or a key file; send tools from `complete`; follow a redirect; fall back to another model or to a call without the provider fields, except the Jev client's one resend without `zdr`; log or keep a prompt, an answer or the key.

## Exports

- `microUsdOf(value)`: dollars with at most six decimals as whole micro-dollars, or null; the budgets' and the reasoner's ceilings parse with it.
- `createOpenRouterClient(options)`, `withBudget(client, budget)` (with `budget.calls`, a count of calls wrappers can share along with their reservations, and `budget.reserveMicroUsd`, what one call reserves, by default `ASSUMED_CALL_MICRO_USD`), `BudgetReached`, `ASSUMED_CALL_MICRO_USD` (10 000 micro-dollars, one cent).
- `createOpenRouterTurnModel({ apiKey, model, deps? })`, the reasoner's model call that sends tools, and `checkToolCalls(reply, allowed)`. A turn uses the personal shapes of the contracts' `turn.ts` and nothing of the shared model contract. It goes to the same host and path as `complete`, with `redirect: "error"`, the same deadline, retries and refusals, the same `provider` object (`data_collection: "deny"` and `require_parameters: true`) on every call with no switch to leave it off, `usage: { include: true }`, the tool definitions, and no `response_format`. A request that does not parse is refused `bad_request` before anything is sent; an answer that does not parse as a `TurnReply`, or holds more than 20 tool calls, is `unavailable`. One malformed tool call (arguments that are not JSON, a name that is no word, a bad id) does not void the reply: it becomes a call named `invalid_tool_call`, which no allow-list holds, so the loop refuses and records it and the reply's cost is still counted. The cost is in micro-dollars rounded up, or null when the answer has none, and the model id is the configured one. `checkToolCalls` marks every call whose name is not in `allowed` `unknown_tool`. `complete` sends no tools.
- `createDecideClient(options)`, `DECIDE_MODELS` (`typesafe/jev-1.13` alone) and `DECIDE_ASSUMED_CALL_MICRO_USD` (2 000): the decide-model client, the same `ModelClient` port on OpenRouter's Decisions surface, `POST /api/alpha/decisions`, with exactly `model`, `state` (each slot's JSON), `questions` (the prompt's instructions, parsed) and `provider` (`zdr` and `data_collection`), `redirect: "error"`, a 20 second deadline and the same retries. An answer of exactly the prompt's question ids, each a `noul` in [0, 1], is the output; no `answers` is `unavailable`; anything else is `ModelOutputRejected`. Zero retention where offered: a request OpenRouter refuses with a 404 whose error message names the data policy or zero retention is sent once more without `zdr`, `data_collection: "deny"` kept, to the same model, and never a third time. The client assumes that wording; no test checks it against the vendor.
- `completeKeyedWithReplay(client, store, request, call, compartments, registry)` and the types `KeyedCall`, `KeyedCallKey`, `KeyedCallRecord`, `KeyedCallStore`: the replay of a call that is not about one evidence item, keyed by `{ point, version, promptId, promptVersion, subject, inputHash }` with the subject `pair:<a_fp>:<b_fp>` (sorted) or `draft:<draft id>`. It keeps the shared `completeWithReplay`'s rules and order, and saves the output, the key, the refs, the compartments and the configured `call.modelId`, never the rendered input.
- `keyLimit({ apiKey, fetch, keyUrl?, deps? })`, `checkSpendCap({ apiKey, fetch, ceilingMicroUsd, keyUrl?, deps? })`, `keyEndpointOf(keyUrl)` and `spendCapEvent(cap)`: the spend-cap check. `keyLimit` sends one `GET https://openrouter.ai/api/v1/key` with the key, `redirect: "error"` and the client's deadline and retries, and answers the key's limit and room left as whole micro-dollars (the limit rounded up, the room left down), or null, and its `limit_reset`; anything it does not recognize throws `unavailable`, and a refusal carries its status and nothing of the body. `keyUrl` is `PI_OPENROUTER_KEY_URL`'s value, which only the box's smoke test sets: `keyEndpointOf` answers OpenRouter's endpoint for unset or empty, the value itself for plain `http://127.0.0.1:<port>/...`, and null for anything else, `localhost` included, since a name is resolved by the host's own lookup, for which `keyLimit` sends nothing and throws `unavailable`. `checkSpendCap` never throws: it answers `ok`, `spend_cap_missing`, `spend_cap_too_high` (a daily limit counts 31 times against the monthly ceiling, a weekly one 5 times), `spend_cap_reached` or `spend_cap_unknown`, the last for every error and for a null room left. `spendCapEvent` is its log line: the code and the two counts, never the key or its label.
- `createAnthropicTurnModel(options)`: the reasoner's turn on Anthropic's Messages API. `options.serverTools` (`ServerTools`) adds Anthropic's `web_search_20260209` and `web_fetch_20260209` after the read tools, on the models those versions run on (Opus 5.5 to 4.6, Sonnet 5.5, 5 and 4.6), with their `max_uses`, a fetched page capped at 10 000 tokens, and its `rules` as a second system block. The reply keeps every content block (`content`), the searches and fetches it ran (`webRequests`, each query or URL) and the searches billed (`webSearchesBilled`); an assistant turn with `content` is sent back unchanged. A `pause_turn` is sent back as it is, at most ten times within the turn's one deadline, and one still paused is `truncated`; a reply whose call has an id that is not one keeps no `content`, so its turn is rebuilt. Each search costs 10 000 micro-dollars on top of the tokens.
- `createAnthropicExtractClient({ apiKey, model, effort?, registry, onUsage, deps? })`, `ANTHROPIC_EFFORTS` and `isAnthropicEffort`: the same extraction port on Anthropic's Messages API (`POST https://api.anthropic.com/v1/messages`, the headers `createAnthropicTurnModel` sends), used by extraction when `PI_EXTRACT_ANTHROPIC_KEY` is set and by `pi extract check --world --vendor anthropic`, the comparison on the synthetic set. The body is `model` (OpenRouter's id or Anthropic's, as `anthropicModelId` reads it), `system` (the instructions), one user message (the data), `max_tokens` 16 000 and `output_config.effort` when an effort is given; no tools, no temperature, the same 180 second deadline and retries. The text blocks are the output, read as `complete` reads `content`, and (`finalJsonFence`) a text that is not JSON but ends with one `json` fence after prose is read from that fence and schema-checked; `stop_reason` `max_tokens` is cut off and `refusal` filtered. The cost comes from the price list in `anthropic-turn.ts`; a model not on it is `cost_missing` at the assumed call cost.
- `createPseudonymiser({ key, known? })`, `Pseudonymiser` and `KnownIdentities`: names, addresses, phone numbers and handles become tokens in a request's body and the originals again in its answer's text. Every vendor request of this package leaves through one function, `send` in `src/retry.ts`, and a client given `deps.pseudonymiser` (every client takes one) has its body pseudonymised there once, before the first attempt, and the text of an answer restored before the client reads it, so the shared checks, the usage row and a saved call all see the originals. It works on the raw body, so the instructions, the data slots, the decide model's state and a turn's tool results, `{ untrusted }` values among them, are all treated alike, and a turn's tool-call arguments come back restored. What it replaces: each `known` value (names, addresses, phones, handles) as a whole word, a one-word name only with its capital; each address and each phone number with a country code or separators the patterns find, never a date or a bare run of digits; and each display name written before an address (`Mira Okafor <mira@example.com>`, raw or escaped), which it also keeps for later requests. A token is `Person_`, `Email_...@pseudonym.invalid`, `Phone_` or `Handle_` and the first 8 hex digits of an HMAC-SHA256 of the value's normal form under `key()` (16 on a clash), so the same value gives the same token in every call and run under one key. A value holding a quote, a backslash, `&`, `<`, `>` or a control character is left as it is. The map back lives in the object, in memory, and nothing logs it. `pi` turns it on with `PI_PSEUDONYMISE`.
- `@intelligence/personal-models/testing`, from `src/test-support/fakes.ts` (`src/test-support/support.ts` holds this package's own tests' values): `fakeModelClient(outputs, calls?)`, which answers by the call key, `<evidenceId>/<inputHash>` first and then the evidence id alone; `fakeDecideClient(outputs, calls?)`, keyed the same way for `jev_screen`, whose outputs are `DecideScreenOutput`s, and for the other Jev prompts keyed `<promptId>:<evidenceId>/<inputHash>`, then `<promptId>:<evidenceId>`, then `<promptId>` alone, parsed by that prompt's schema; `fakeKeyedCallStore(seed?)`, an in-memory `KeyedCallStore` whose `records()` returns copies; and `fakeKeyEndpoint({ limit?, remaining?, reset? })`, a key endpoint that answers that limit in dollars (by default 5, all of it left, no reset), and counts its calls; and `recordedTurn(over, modelId)`, a recorded model's turn with no text or tool calls and fixed tokens and cost, `over` laid on top.

## What the client assumes of OpenRouter

The client is tested against a fake `fetch` that answers in the shape written here. What follows is what it assumes of OpenRouter's API. No test checks these against the vendor; the two scripts under "Checking the request shape" and "Checking Jev's request shape" do, run by the owner with a real key. The extraction call assumes seven:

1. the request-level `provider.data_collection` field, with `provider.require_parameters`. `provider.zdr` is not sent: OpenRouter's public model metadata for `openai/gpt-6-luna`, read on 2026-10-04 with no key, lists no `temperature` among its `supported_parameters`, and its zero-retention endpoints are Azure's only, which take `max_completion_tokens` and not `max_tokens`, so with it no endpoint qualified;
2. `response_format` of type `json_object`;
3. the request-level `usage: { include: true }`, `usage.cost`, and that its unit is US dollars (the vendor's documentation calls the unit credits);
4. `finish_reason` and its values, `stop`, `length`, `content_filter`, `tool_calls` and `error` among them;
5. the status codes, and that an error can arrive as a `200` whose body holds an `error` object and no `choices`;
6. what a request answers when no provider serves the model under the request's parameters. The vendor's documentation, read on 2026-10-03, gives `503` with `Retry-After`, which this client retries and then calls `unavailable`; a `4xx` would be `refused`. Either way the error carries its status in `status` (`http_503`, `http_404`), which `pi extract check` prints on its `accepted` line;
7. whether the configured extraction model takes `max_tokens: 16000` (the arithmetic is at `MAX_TOKENS` in `src/openrouter.ts`) under `require_parameters` (the OpenAI and Bedrock endpoints list it; `temperature` is not sent, since replay of saved calls, not sampling, is what makes extraction repeatable), and whether it spends its answer's tokens on reasoning before it writes, which would make cut-off answers common.

The turn call assumes three more:

8. the tool fields: `tools` as `{ type: "function", function: { name, description, parameters } }`, an answer's `message.tool_calls` as `{ id, type: "function", function: { name, arguments } }` with `arguments` a JSON string, an assistant message sent back with its `tool_calls`, and a tool result sent as `{ role: "tool", tool_call_id, content }`;
9. the usage-accounting field `usage: { include: true }`, and whether `usage.cost` arrives without it; if it does, the field is dropped from the turn call and from `complete`'s body together;
10. whether the configured reasoner model takes tools under `require_parameters`.

The spend-cap check assumes one more, which `scripts/check-request.ts` reads for the key it is given:

11. the key endpoint, `GET /api/v1/key`, answering `{ data: { limit, limit_remaining, limit_reset } }`, the first two in dollars or null, `limit_reset` one of `daily`, `weekly`, `monthly` or null. A different shape refuses every run with `spend_cap_unknown`.

## Checking the request shape

`scripts/check-request.ts` sends one request, built by hand, to OpenRouter. It is the only file in this package that reaches a vendor, and the only one that writes to standard output. No test runs it. It reads the key on standard input, never as an argument or in the environment.

It prints one line per check, to standard output: the check's name, `ok` or `failed`, and only what is needed to judge it. `status`, the status code; `retention_accepted`, that the request with `provider.data_collection` and `provider.require_parameters` was not refused; `refusal`, when it was, the status code and whether the body holds an `error` object; `json_output`, that the content parses as JSON; `finish_reason`, its value; `tokens`, the names of the token fields found; `cost`, the field and its number, to compare with the OpenRouter dashboard as US dollars; `model`, whether the answer names one. Then it reads the key endpoint with the same key, even when the request was refused, and prints `key_status`, the status code; `key_fields`, which of `limit`, `limit_remaining` and `limit_reset` the answer's `data` holds; `key_numbers`, failed with the field's name when a figure is not a finite number or the limit is negative, as the check refuses; `limit_reset`, its word, `null` or `absent`; and one line `limit_micro_usd=<n> remaining_micro_usd=<n> reset=<word or none>`, or `limit: none` for a key with no limit. It never prints the key, the key's label or the answer's content. A line that fails is fixed in this package, in a pull request of its own.

## Checking Jev's request shape

`scripts/check-decide-model.ts` sends one hand-built request to the Decisions surface with the provider fields, and prints `status`, `provider_accepted`, `answers` (the three ids, each a `noul`), `cost` and `tokens`. It never prints a probability, the key or the answer's content. It reads the extraction key on standard input.
