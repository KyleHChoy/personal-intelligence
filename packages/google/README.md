# @intelligence/personal-google

The shared `Connector` for `google_mail`, `google_calendar` and `google_docs` over plain REST, the People connector for `google_contacts`, mail at depth `full`, calendar at depth `headers` and Drive files at `full` for a Google Doc read and `headers` for any other file, the `HttpPort` that carries every Google call, and the OAuth loopback flow that gets a refresh token for one Google account.

- **May import:** `@intelligence/contracts` and `@intelligence/personal-core`, and nothing else in this repository; its tests read a rendered message back with the core's parse. Otherwise only Node's `fetch`, `crypto` and `http`.
- **Runs with:** one account's OAuth client id and secret and that account label's refresh token per call, handed in by `pi` as parameters (an account may use its own client); never read from disk, the environment or the database here. One connector serves one source account, and the package keeps nothing between calls or across accounts.
- **Entry `./send`**: the write side alone, reaching the revoke URL and the send URL and no other. Only `apps/pi/src/send/send.ts` imports it, which `src/send.test.ts` checks. `revokeSendToken(refreshToken, deps?)` is one form `POST` to the revoke URL, true only for a 200 and never throwing. `createSendHttp({ accessToken, deps? })` is the read port with that one token, never refreshed, refusing with `off_allowlist`, before anything is sent, anything but a write `POST` to the send URL. `renderMessage(payload, from)` is the message's bytes, pure: one `text/plain` part in base64 and a fixed set of headers alone.
- **Must never:** request an attachment's bytes, text Gmail holds apart from a message's answer, an event's description, or a send or modify scope from the connectors; fetch, in a listing, a message older than the listing's window; write to Google outside the entry `./send`; store anything; advance its own cursor; follow anything an item says.
- **Mail:** a message inside the window is fetched whole, one `messages.get` with `format=full`: its listed headers, its text and HTML, and each attachment's name, type and size. A message older than the window is never fetched: a reconciling listing names it by id alone. An attachment's bytes are never fetched. A connector paces every Gmail request by quota units (11 ms a unit: a fetch each 220 ms), fetches up to four messages at once, rides out a rate limit for up to five minutes a run, and a page of messages is bounded by 32 MiB of payloads as well as by count.
- **Ties:** `createTiesReader` lists older mail by ids and asks for each message's who-and-when headers and fields alone, under the same pace and the same grant: no subject, snippet or body.
- **Drive and Docs (GD):** one grant per source family, each its own consent and refresh token: `drive` asks for `drive.metadata.readonly` and `documents.readonly` and nothing else, and the Drive connector refuses a credential that holds any other set. Nothing is in scope until the owner names a root: with none the connector makes no call. A file outside every root is never handed over and its content never asked for; its metadata passes through the account-wide listing and feed and none of it is kept. Only a Google Doc in scope whose owner allows download is read, with one `documents.get`; any other file is an item made from its name, type, size and times. No call asks for an export, a download, comments, revisions, permissions or a thumbnail, or sets `supportsAllDrives`. The connector paces its document fetches, at most one every 250 ms, and a page holds at most 25 of them and 32 MiB of payloads. Its folder map (ids and parents only) is kept for the connector's life, one sync run, a stated deviation from "nothing in memory".
- **Logs nothing.** It takes no logger. A failure surfaces only as a `GoogleError`, which carries a code and an HTTP status and nothing else: no message from Google, no URL, no token, no header value and no cause.
- **Tests:** every test runs on a fake `fetch`, with sleep, clock and random injected through `GoogleDeps`. Nothing in `src/` calls Google from a test.

## What it exports

| Export | What |
| --- | --- |
| `createGoogleHttp({ tokens, deps? })` | The `HttpPort` every Google call goes through. It adds the bearer token, applies each request's own deadline, and retries a `read` up to five attempts in all with backoff or `Retry-After`. A `read` answered 401 gets one new token and one more attempt, outside that count. A `write` is sent once, whatever the answer, a 401 included. A token it cannot get fails the request with that error and no status. |
| `GoogleDeps`, `TokenSource` | Types: the injected `fetch`, `sleep`, `now`, `random` and `timeoutMs`; and where the port gets an access token. |
| `GoogleError` | The only error this package throws on purpose. `code` is one of `unauthorized`, `forbidden`, `not_found`, `rate_limited`, `unavailable`, `bad_response`, `bad_request`, `bad_cursor`, `oauth_failed`, `off_allowlist`, `too_large`, `scope_mismatch`, `wrong_account`, `sync_token_expired`, `too_many_folders`. |
| `GOOGLE_SCOPES` | The two read-only scopes: `gmail.readonly` and `calendar.events.readonly`. The mail grant's, `scopesFor("mail")`, and the only ones a connector's credential may hold. |
| `GrantKind`, `scopesFor`, `grantedScopesFor` | `"mail" \| "send" \| "drive" \| "contacts"`: one grant per source family, each its own consent and refresh token. `scopesFor(grant)` and `grantedScopesFor(grant)` in `src/http.ts` give the set a consent requests and the set its token answer must name exactly; `send`'s are `gmail.send`, `openid` and `email` (granted as `userinfo.email`); `drive`'s are `drive.metadata.readonly` and `documents.readonly`; `contacts`'s are `contacts.readonly`, `openid` and `email`. `scopesFor` is also the credential a contacts connector takes. |
| `MAX_DOCUMENT_ANSWER_BYTES` | 8 MiB: the bound of the port a Drive connector is given, `createGoogleHttp({ tokens, deps, maxAnswerBytes })`. A document whose answer is over it is `too_large`, an item with no text. |
| `driveAbout(http, deps?)`, `driveFolder(http, id, deps?)` | The address a Drive token belongs to (`about.get`); and a folder's own id when `id` names a folder the account can see, not trashed and in no shared drive, else null (`root` answers My Drive's id). |
| `MAX_ANSWER_BYTES` | 4 MiB, the most the port reads of any answer. One over it fails `too_large`, is never retried and never parsed; a message whose answer is over it is read again by its headers. |
| `pkcePair`, `pkceChallenge`, `buildAuthUrl` | PKCE with S256, and the consent URL for one grant's scopes, with offline access, `prompt=consent`, an optional `login_hint`, and never `include_granted_scopes`. |
| `listenForCode(state, port?, { timeoutMs? }?)` | A one-shot listener on `127.0.0.1` that settles on the redirect carrying the matching state. |
| `exchangeCode`, `tokenSource` | Each takes a `grant`. The code for a refresh token, refused with `scope_mismatch` unless the answer's scope is exactly `grantedScopesFor(grant)`; for `send` and `contacts` it takes `expectedAddress` (refused for `mail` and `drive`) and refuses with `wrong_account` unless the same answer's id token has `email_verified` true and that `email`, without case. And access tokens from a refresh token, kept in memory until a minute before they expire, a refresh answer held to the same exact set; for `mail`, one that names no scope is accepted while `MAIL_REFRESH_ACCEPTS_NO_SCOPE` (in `src/oauth.ts`) is true, until the live check shows `refresh_answer_carries_scope` and `refresh_scope_exact`. The exchange is sent once; a refresh is retried as a read is. Either answered 400 or 401 is `oauth_failed` at once. |
| `gmailProfile(http, deps?)` | The account's address and current history id. |
| `gmailSendAs(http, deps?)` | The addresses the account sends from, its primary and every verified alias, lower-cased and sorted, read with `gmail.readonly`. |
| `createGoogleConnector(id, credential, http, options?, deps?)` | A `PersonalConnector`, which is a shared `Connector`, for `google_mail`, `google_calendar` or `google_docs`. For `google_docs`, `options.roots` names the roots and `options.stored(id, tag)` says what is already stored or erased, so it is not fetched again; a listing of every file in scope, from the change token taken before it, ends `complete` in Drive's changes feed, and a feed entry that can change a file's root ends the feed in a new listing. A file that left scope is named in the page's `left`. `listChanges` returns one page: a listing first (`options.since` is its window), then Gmail history or Calendar sync-token changes, through the same call. A Gmail listing reads sent mail and then the rest of the window; after a reset or an expired history id it then names what is older by id alone. Gmail history covers added and deleted messages and label changes; a relabelled message is fetched again only when a deriving label changed, and an added message the owner sent brings its thread's conditional messages. Items are made only by `gmailItem` and `calendarItem` of `@intelligence/personal-core`. |

| `createPeopleConnector(credential, http, deps?)` | A `PersonalConnector` for `google_contacts`. It refuses a credential for another connector (`off_allowlist`) or whose scopes are not exactly `scopesFor("contacts")`, as sets (`scope_mismatch`). Every request is a `GET` of `people/me/connections` with `PEOPLE_FIELDS`, `sources=READ_SOURCE_TYPE_CONTACT`, `pageSize=PEOPLE_PAGE_SIZE` (1000), `requestSyncToken=true`, and a page token or a sync token (both while paging a sync). A listing ends `complete` with the sync token; a sync page hands over changes (`live`) and deletions; an expired sync token (410, or `sync_token_expired`) starts a new listing in the same call; a page with more unreadable contacts than `CONTACT_LIMITS`' bound fails `bad_response`. Items are made only by `whitelistedContact` and `contactItem` of `@intelligence/personal-core`. `resetCursor()` is `null` and `syncAccessList` makes no call. |
| `PEOPLE_FIELDS`, `PEOPLE_PAGE_SIZE` | The People connector's fixed field list and page size. |

The cursor codec (`src/cursor.ts`) is internal: a cursor is opaque to everything outside this package.

## The live check

`scripts/check-google.ts` is not part of the package, nor are the files it runs from: `check-google-kit.ts` (what every mode shares), `check-google-mail.ts` and `check-google-mail-parts.ts` (the mail and calendar mode), and `check-google-drive.ts` (the `--drive` mode); the contacts mode is in `check-google.ts` itself. It is the script the owner runs against a throwaway Google account, to confirm each behaviour of Google's that the connectors assume and no test can check. Only the owner runs it; no test does. With `--contacts` (and `PI_CHECK_ADDRESS`, the throwaway account's address) it runs only the contacts part of the live check: the contacts grant's scope and account check, the People listing and sync, and the People behaviour the contacts connector assumes; it keeps no token for that part.

`scripts/live-send-check.ts` is not part of the package either. It is the live send check, run by the owner against a throwaway account, with the send client, before `pi send connect` is run on any real account. It is the one file outside `apps/pi/src/send/send.ts` that imports the entry `./send`, and no process runs it.
